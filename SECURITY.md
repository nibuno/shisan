# Security Policy

## Reporting a vulnerability

**Please do not report security issues in public issues or pull requests.**

Use GitHub's private vulnerability reporting on this repository:
[Report a vulnerability](https://github.com/nibuno/shisan-public/security/advisories/new).
It opens a private channel visible only to the maintainers.

Please include:

- what the issue is and roughly how severe you think it is
- the steps to reproduce it
- the version or commit you tested

This is a side project maintained by one person, so please allow a few days for
an initial response.

## Scope

shisan stores household asset balances, which is sensitive personal data.
Reports about the following are especially welcome:

- **anything that lets one household read or modify another household's data**
- authentication or session handling flaws
- CSRF, XSS, or injection
- secrets or personal data leaking through logs, errors, or API responses

Out of scope: findings that only apply to a deliberately misconfigured
deployment (for example running with `DJANGO_DEBUG=True` on a public host), and
reports generated by automated scanners with no demonstrated impact.

## For self-hosters

shisan does not manage your infrastructure. When you deploy it:

- serve it over HTTPS and set `SESSION_COOKIE_SECURE=True` and
  `CSRF_COOKIE_SECURE=True`
- set a long random `DJANGO_SECRET_KEY` and keep it out of version control
- set `DJANGO_ALLOWED_HOSTS` to your own hostnames
- keep the database on a private network and back it up
- run `python manage.py check --deploy` and expect zero warnings
